# Требования безопасности

## Нормативная база

- **Приказ ФСТЭК №17** — защита ГИС (меры ИАФ, УПД, РСБ, ЗИС, ОЦЛ)
- **152-ФЗ** — персональные данные (категория 4, УЗ-4 по ПП-1119)
- **ISO/IEC 27001:2022** — управление ИБ
- **ГОСТ Р 58256-2018** — идентификация и аутентификация

## Персональные данные

### Состав ПДн
| Данные | Чувствительность | Хранение | Маскирование |
|--------|-----------------|----------|-------------|
| Телефон | Высокая | AES-256 (field encryption) | +7916***4567 |
| TOTP-секреты | Высокая | AES-256 (отдельный ключ) | Не передаётся |
| ФИО | Средняя | Открытый текст | Иванов И.А. |
| Email | Средняя | Открытый текст | iva***@domain.ru |
| IP, User-Agent | Средняя | Открытый текст (TTL 12 мес) | Только для admin |
| user_id в Workflow | Низкая | UUID (псевдоним) | Не маскируется |

### Сроки хранения
| Данные | Срок | После срока |
|--------|------|------------|
| ФИО, email, должность | До деактивации + 30 дней | Обезличивание |
| Телефон | До деактивации + 30 дней | Удаление |
| Журнал входов (IP, UA) | 12 месяцев | Удаление (cron ежедневно) |
| История паролей | 10 записей FIFO | Ротация |
| Сессии | 7 дней | Автоудаление |
| История согласований | 5 лет | Архив → удаление |

### Псевдонимизация
Workflow и Catalog не хранят ФИО/email/телефон. Оперируют user_id (UUID). ФИО для отображения запрашивается у Auth через /internal/users/batch.

## Меры защиты (маппинг на стандарты)

### ИАФ — Идентификация и аутентификация
| Мера | Реализация | ISO 27001 |
|------|-----------|-----------|
| ИАФ.1 | UUID идентификатор, email логин, аккаунты создаются администратором | A.9.2.1 |
| ИАФ.3 | TOTP (RFC 6238), обязателен для pm, backup codes | A.9.4.2 |
| ИАФ.4 | Argon2id, 12 символов, история 10, срок 90 дней, блокировка 5 попыток | A.9.4.3 |
| ИАФ.5 | Единообразная ошибка «Неверный email или пароль» | A.9.4.2 |

### УПД — Управление доступом
| Мера | Реализация | ISO 27001 |
|------|-----------|-----------|
| УПД.1 | RBAC: user × project × role. 38 permissions. Создание аккаунтов — только admin своей стороны | A.9.1.1 |
| УПД.2 | JWT RS256 (15 мин) + refresh (7 дней, ротация). Idle 30 мин. Max 3 сессии | A.9.4.2 |
| УПД.3 | 6 ролей с разными наборами permissions | A.9.1.2 |
| УПД.4 | Separation of duties: pm согласует, admin администрирует, analyst рецензирует | A.9.1.1 |

### РСБ — Регистрация событий
| Мера | Реализация | ISO 27001 |
|------|-----------|-----------|
| РСБ.1 | Логируются: входы, смена пароля, роли, CRUD функций/ставок, согласования, отказы доступа | A.12.4.1 |
| РСБ.2 | Единая модель: timestamp, user, action, resource, changes (JSON diff), correlation_id | A.12.4.1 |
| РСБ.3 | Append-only (только INSERT), хранение 12 мес, доступ к чтению — admin + superadmin | A.12.4.2 |

### ЗИС — Защита информационной системы
| Мера | Реализация | ISO 27001 |
|------|-----------|-----------|
| ЗИС.3 | TLS 1.2+ (nginx), межсервисные HTTPS, HSTS, X-Content-Type-Options | A.13.1.1 |
| ЗИС.5 | Rate limiting /auth/login (20/min), ограничение параллельных генераций | A.13.1.3 |
| ЗИС.7 | Field encryption (AES-256), маскирование в API, псевдонимизация между сервисами | A.10.1.1 |

### ОЦЛ — Обеспечение целостности
| Мера | Реализация | ISO 27001 |
|------|-----------|-----------|
| ОЦЛ.1 | SHA-256 при генерации документа, проверка при выгрузке, расхождение → блокировка + аудит | A.14.2.2 |

## Ограничения MVP (план на продакшен)

| Ограничение | MVP | Продакшен |
|------------|-----|-----------|
| Ключи шифрования | Переменные окружения | HashiCorp Vault / HSM |
| TLS-сертификат | Самоподписанный | Аккредитованный УЦ |
| Мониторинг | structlog JSON | Prometheus + Grafana + Loki |
| Резервное копирование | Нет | PostgreSQL pg_dump + MongoDB mongodump, шифрование |
| WAF | Нет | nginx ModSecurity / CloudFlare |
