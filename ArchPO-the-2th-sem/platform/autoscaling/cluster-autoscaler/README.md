# Дизайн Cluster Autoscaler

Cluster Autoscaler выбран в этом проекте как подход к автомасштабированию worker-нод.

## Область Применения

HPA масштабирует поды и может быть проверен локально в k3d/k3s при наличии metrics-server.

Cluster Autoscaler масштабирует worker-ноды. Он следит за подами, которые не могут быть запланированы, и просит инфраструктурный provider добавить ноды. Также он может удалять недоиспользуемые ноды, если их можно безопасно drain-ить.

## Ограничение Локального k3d/k3s

Локальный k3d/k3s-кластер создает worker-ноды как Docker-контейнеры. Cluster Autoscaler не может самостоятельно создавать или удалять эти контейнеры, если он не подключен к поддерживаемому инфраструктурному backend.

Реальное автомасштабирование worker-нод в локальных окружениях требует один из вариантов:

- интеграция с cloud provider;
- Cluster API плюс infrastructure provider;
- custom или provider-specific backend, который умеет управлять node groups.

У Karpenter есть то же практическое требование: ему нужен provider, который умеет provision-ить машины.

## Решение В Проекте

Для Block 1:

- HPA используется для локальной проверки автомасштабирования.
- Cluster Autoscaler документируется как дизайн масштабирования worker-нод.
- `values.example.yaml` содержит только placeholders.
- Облачные учетные данные и секреты не добавляются.

## Пример Values

Файл с примером values намеренно не является рабочей cloud-конфигурацией:

```sh
cat platform/autoscaling/cluster-autoscaler/values.example.yaml
```

Перед использованием Cluster Autoscaler в реальной среде нужно заменить placeholders значениями для выбранного provider и настроить учетные данные вне репозитория.
