# ГОСТ 34.603-92 — Виды испытаний автоматизированных систем

## Назначение стандарта

ГОСТ 34.603-92 устанавливает виды испытаний автоматизированных систем (АС), порядок их проведения и требования к документации по результатам испытаний.

---

## Виды испытаний (раздел 3)

| Вид испытания | Назначение | Когда проводится |
|---|---|---|
| Предварительные испытания | Проверка соответствия ТЗ перед опытной эксплуатацией | После завершения разработки |
| Опытная эксплуатация | Проверка в реальных условиях | После предварительных испытаний |
| Приемочные испытания | Окончательная приемка | После опытной эксплуатации |

---

## Методы испытаний (п. 5)

### 5.1 Проверка (Check)
Метод испытания, при котором осуществляется функционирование АС в реальных условиях. Применяется для оценки правильности выполнения функций.

**Когда использовать:** функции с измеримым результатом (отчет создан, данные сохранены).

### 5.2 Демонстрация (Demonstration)
Метод испытания, при котором осуществляется наглядное представление функционирования АС. Применяется для оценки работоспособности.

**Когда использовать:** пользовательский интерфейс, визуальное отображение данных.

### 5.3 Тестирование (Testing)
Метод испытания с использованием специальных тестовых воздействий для оценки граничных значений и нестандартных ситуаций.

**Когда использовать:** проверка защиты от некорректного ввода, граничные условия.

### 5.4 Анализ (Analysis)
Метод испытания путем изучения документации и кода без запуска системы.

**Когда использовать:** оценка архитектурных решений, соответствие стандартам.

---

## Структура программы и методики испытаний (ПМИ) — раздел 4

ПМИ должна содержать:

1. **Введение** — наименование АС, основание для испытаний
2. **Объект испытаний** — наименование, назначение АС
3. **Цель испытаний** — перечень проверяемых свойств
4. **Требования к программе испытаний** — условия, объём, методы
5. **Требования к методике испытаний** — критерии оценки результатов
6. **Средства и условия проведения испытаний** — оборудование, ПО, персонал
7. **Порядок проведения испытаний** — последовательность этапов
8. **Методики испытаний** — детальное описание каждой проверки

## Раздел «Результаты испытаний» — типовая таблица

| № | Наименование функции | Метод испытания | Результат | Соответствие ТЗ |
|---|---|---|---|---|
| 1 | Аутентификация пользователя | Проверка | Пользователь авторизован, получен JWT | Соответствует |
| 2 | Генерация ТЗ | Проверка | Файл .docx создан, стили применены | Соответствует |
| 3 | Согласование | Демонстрация | Оба РП оставили решение, раунд завершен | Соответствует |

---

## Критерии оценки результатов (п. 5.5)

- **Соответствует** — функция работает согласно ТЗ без замечаний
- **Соответствует частично** — функция работает, но с незначительными отклонениями
- **Не соответствует** — функция не выполняет требования ТЗ

---

## Требования к фиксации результатов

При проведении испытаний методом «Проверка» или «Тестирование» обязательно фиксируются:
- скриншоты экрана в момент проверки
- значения параметров, введенных и полученных в ходе испытания
- временные метки каждого действия
- HTTP-ответы API при автоматизированной проверке

---

## Типичные ошибки при составлении ПМИ

1. Не указан метод испытания — недопустимо
2. Ожидаемый результат сформулирован расплывчато («работает») — недопустимо
3. Отсутствует ссылка на пункт ТЗ или ГОСТ — замечание проверяющего
4. Нет скриншота для визуально проверяемых результатов — замечание
