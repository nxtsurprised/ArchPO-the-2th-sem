# Каталог ошибок и интерпретаций

Справочник для агента Протоколиста при классификации результатов испытаний.

---

## HTTP-коды ответа

| Код | Значение | Допустимо в тесте? |
|---|---|---|
| 200 | OK | Да — успех |
| 201 | Created | Да — объект создан |
| 204 | No Content | Да — удаление / обновление без тела |
| 400 | Bad Request | Зависит от теста (для негативных — да) |
| 401 | Unauthorized | Только для негативных тестов |
| 403 | Forbidden | Только для тестов RBAC |
| 404 | Not Found | Только если объект не существует |
| 409 | Conflict | Для тестов дубликатов / блокировки |
| 422 | Unprocessable Entity | Ошибка валидации — для негативных тестов |
| 500 | Internal Server Error | Никогда не допустимо |

## Коды ошибок бизнес-логики (из API)

| Код ошибки | Где возникает | Интерпретация |
|---|---|---|
| `INVALID_CREDENTIALS` | Auth: POST /auth/login | Неверный email или пароль — ожидаемо |
| `ACCOUNT_LOCKED` | Auth: POST /auth/login | Аккаунт заблокирован после 5 попыток |
| `TOKEN_EXPIRED` | Любой защищенный эндпоинт | Токен истек, нужна повторная авторизация |
| `PERMISSION_DENIED` | Защищенный эндпоинт | Нет прав на операцию |
| `DOCUMENT_LOCKED` | Catalog: PUT /documents/:id | Документ на согласовании, нельзя редактировать |
| `APPROVAL_IN_PROGRESS` | Workflow | Согласование уже активно |
| `ROUND_NOT_COMPLETE` | Workflow: GET /approvals/:id | Не все РП приняли решение |
| `DUPLICATE_ENTRY` | Catalog: POST /templates | Запись с таким именем уже существует |
| `INVALID_TRANSITION` | Workflow | Недопустимый переход состояния |

## Типовые ошибки выполнения тестов и их интерпретация

### Элемент не найден (TimeoutError)
**Причина:** Селектор неверный или элемент не появился.  
**Действие:** Сделать скриншот, проверить DOM, попробовать альтернативный селектор.  
**Вердикт:** Не засчитывать шаг как провал до исчерпания альтернатив.

### Редирект вместо ожидаемой страницы
**Причина:** Нет прав доступа, токен истек, или маршрут изменился.  
**Действие:** Проверить URL, проверить наличие токена, авторизоваться заново.  
**Вердикт:** Если редирект на /login — проблема авторизации.

### Медленный ответ (timeout > 5 сек)
**Причина:** Сервис перегружен или зависание запроса.  
**Действие:** Повторить шаг, зафиксировать время ответа.  
**Вердикт:** Если повторно — замечание о производительности в ПМИ.

### 500 Internal Server Error
**Причина:** Ошибка на стороне сервера.  
**Действие:** Зафиксировать запрос и ответ, остановить тест данной функции.  
**Вердикт:** «Не соответствует» — критическая ошибка.

## Критерии вердикта по результатам теста

### «Соответствует» — все условия:
- Все шаги выполнены успешно (status: passed)
- Фактический результат совпадает с ожидаемым
- HTTP-коды ответа соответствуют ожидаемым
- Нет сообщений об ошибках в UI

### «Соответствует частично» — одно или несколько:
- 1-2 шага завершились с незначительными отклонениями (напр., другой текст сообщения)
- Функция работает, но с задержкой > 2 сек
- Присутствуют косметические дефекты UI, не влияющие на функциональность
- Опциональные поля не отображаются, но обязательные — корректно

### «Не соответствует» — хотя бы одно:
- Ключевой шаг завершился с ошибкой (status: failed)
- Получен HTTP 500
- Критическая функция недоступна
- Данные искажены или не сохранены

## Как записывать наблюдения в ПМИ

Используй шаблон:
> «В ходе испытания [описание действия]. Наблюдаемый результат: [что произошло].
> Ожидаемый результат: [что должно было произойти].
> Вывод: [соответствует / не соответствует]»

Пример:
> «В ходе испытания выполнен вход в систему с корректными учетными данными.
> Наблюдаемый результат: пользователь перенаправлен на дашборд, JWT-токен получен.
> Ожидаемый результат: успешная авторизация и перенаправление на дашборд.
> Вывод: соответствует.»
